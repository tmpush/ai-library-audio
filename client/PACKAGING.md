# Сборка и оставшаяся приёмка

С версии 0.3 установленная программа использует нативный Rust / egui-интерфейс. Актуальные команды — в `native/README.md` и `scripts/build_native.ps1`. Ниже сохранена инструкция прежней Tauri-сборки; общий Python/CUDA sidecar остаётся тем же. `install_desktop.ps1` теперь устанавливает бинарный файл из `client/native/target/release`.

## Полная локальная Windows-сборка

Для CUDA-дистрибутива используется каталог с библиотеками: многогигабайтный PyTorch не распаковывается при каждом запуске. Веса Qwen остаются отдельными локальными файлами.

```powershell
uv pip install --python .venv-tts/Scripts/python.exe pyinstaller==6.22.3
.venv-tts/Scripts/python.exe scripts/build_sidecar.py --with-tts --onedir --ffmpeg-dir build/ffmpeg-runtime
.venv/Scripts/python.exe scripts/verify_sidecar.py --executable build/sidecar-full/books-engine/books-engine.exe
.venv/Scripts/python.exe scripts/verify_frozen_license.py --executable build/sidecar-full/books-engine/books-engine.exe --with-tts
cd client/ui
npm run tauri build -- --no-bundle --features bundled-engine-dir --config src-tauri/tauri.full.json
cd ../..
powershell -File scripts/install_desktop.ps1
```

`build/ffmpeg-runtime` должен содержать проверенный ffmpeg.exe и его LICENSE/README. Скрипт установки копирует готовый `.exe`, Python/CUDA runtime и FFmpeg в `%LOCALAPPDATA%/Programs/LocalBooksStudio`, затем создаёт ярлыки на рабочем столе и в меню «Пуск». Это локальная установка из каталога, без MSI/NSIS и подписи издателя. Для запуска не нужны исходники Python или Node; выбранную папку весов модели сохранять необходимо.

На этой машине полный frozen exe прошёл настоящий CUDA Graphs синтез и экспорт MP3/M4B с системным PATH без Python/Node/FFmpeg, а также активацию/перезапуск/отзыв временной лицензии (`artifacts/frozen-full-check.json`). Импорты научных библиотек выполняются на главном потоке до готовности API: это устраняет обнаруженные зависания их нативной инициализации в фоновом потоке Windows. Обычный измеренный старт полного обработчика — около 8 секунд; первый запуск новой копии может быть дольше. Веса при открытии окна не загружаются.

Для однократного переноса библиотеки: остановить предпросмотр (`.venv/Scripts/python.exe -m client.preview --stop`), затем запустить `scripts/migrate_preview.py`. Скрипт сохраняет исходные данные, переносит SQLite через backup API и отказывается перезаписывать уже существующую десктопную библиотеку. Новый каталог данных — `%APPDATA%/app.localbooks.studio`. Проверка синтеза использует временный сервер и временную лицензию; они не включаются в установленное приложение.

## Проверенная часть

Из корня проекта на Windows x64:

```powershell
uv sync --frozen
uv run python scripts/build_sidecar.py
uv run python scripts/verify_sidecar.py
```

Получаются `build/sidecar/books-engine.exe` и копия с суффиксом архитектуры в `client/ui/src-tauri/binaries`. Проверка запускает настоящий `.exe`, использует временную библиотеку и завершает процесс. Проверяются токен, три формата, числа, обложки и языковые данные.

`scripts/verify_frozen_license.py` — отдельная интеграционная проверка системного хранилища и лицензии в `.exe`. Она запускает временный сервер, три раза запускает обработчик и очищает созданный тестовый секрет. Существующий секрет приложения сохраняется. Этот тест не использует модель и не заменяет тесты macOS.

## Нативное окно

На подготовленной сборочной машине с Rust и системными средствами сборки сначала соберите sidecar, затем:

```powershell
cd client/ui
npm ci
npm run tauri build
```

Перед сборкой задайте `BOOKS_LICENSE_URL` (HTTPS) и `BOOKS_LICENSE_PUBLIC_KEY` (публичный Ed25519-ключ в base64). Они встраиваются в нативный код. Приватный ключ остаётся только на сервере.

29 октября 2026 пользователь разрешил установку средств сборки: установлены Rust/Cargo 1.99.1 MSVC и Visual Studio Build Tools 2022 17.14.42 с Windows SDK. Для полной CUDA-сборки используется описанный выше каталог приложения.

Собирать нужно отдельно для Windows x64, macOS Intel и Apple Silicon. Скрипт выбирает суффикс по машине сборки. `.github/workflows/desktop-smoke.yml` подготовлен для ручного запуска на Windows/macOS runners, но не запускался. Его артефакты предназначены только для подготовки книг: в них по умолчанию нет TTS и FFmpeg. Архитектуру macOS runner следует проверить в отчёте; один runner не проверяет обе архитектуры.

## Сборка с озвучкой и экспортом

Тяжёлые зависимости устанавливаются только после согласования, в отдельное окружение `.venv-tts`. Нужны проверенный набор Qwen/PyTorch для конкретной ОС и отдельная фиксация версий. Веса модели не включаются и скачиваются пользователем отдельно с показом размера.

На текущей Windows проверены исходники с `requirements-tts-windows.lock.txt`, включая faster-qwen3-tts 0.3.2 и CUDA Graphs. Полная сборка включает этот пакет и его metadata. Длинный GPU-тест замороженной сборки и macOS требуют отдельной проверки; macOS использует обычный движок.

`build_sidecar.py --with-tts --onedir` собирает уже установленные TTS-пакеты. Этот путь использован для локальной Windows-сборки. Отдельная проверка на чистой машине остаётся обязательной до распространения.

Для экспорта без внешнего PATH предусмотрен `--ffmpeg-dir ПОЛНЫЙ_ПУТЬ`: каталог должен содержать FFmpeg, необходимые DLL и файлы лицензий выбранной поставки. Он включается как `tools/`; обработчик ищет встроенный FFmpeg раньше системного. Полная Windows-сборка включает FFmpeg 9.0.2, LICENSE и README его поставки; старый минимальный sidecar остаётся без него.

Правила размещения ресурсов основаны на [документации PyInstaller](https://pyinstaller.org/en/stable/runtime-information.html), команды оболочки — на [документации Tauri](https://v2.tauri.app/distribute/).

## До выпуска

1. Проверить реальный синтез и голос: WAV 15 секунд, две контрольные фразы, русский и смешанные языки.
2. Измерить CPU и CUDA на одной главе 10–15 тысяч знаков, отдельно первый запуск и повторный. Записать модель/ревизию, версии, устройство, время работы и длительность WAV. RTF = время обработки / длительность аудио; не использовать показатели технического тестового сигнала как скорость модели.
3. Проверить паузу, принудительное закрытие и восстановление на реальном TTS; проверить обложку и главы M4B в проигрывателях.
4. Собрать Tauri с TTS и FFmpeg, проверить без установленного Python/Node/FFmpeg на чистых Windows и двух архитектурах macOS. На Apple отдельно проверить CPU/MPS.
5. Настроить подпись/нотаризацию, повторить запуск скачанного установщика, включить необходимые лицензионные уведомления.
