# Сервер лицензий

## Локальная установка владельца (29 октября 2026)

На этом компьютере настроен постоянный сервер `http://127.0.0.1:8791`, привязанный только к loopback. Админка находится по этому же адресу. Сервер использует SQLite и исходную политику: 2 устройства, 7 дней офлайн, проверка каждые 24 часа. Владельцу выпущен годовой ключ; он активирован в установленной программе через штатный интерфейс.

- Исполняемый файл: `%LOCALAPPDATA%/Programs/LocalBooksLicenseServer/books-license-server.exe`.
- Автозапуск: `%APPDATA%/Microsoft/Windows/Start Menu/Programs/Startup/Local Books License Server.lnk`. Сервер запускается без консольного окна при входе пользователя. Запуск именно через этот ярлык проверен; перезагрузка Windows в ходе настройки не выполнялась.
- Конфигурация, приватный ключ подписи и база: `%APPDATA%/LocalBooksLicenseServer`. Каталог доступен текущему пользователю и SYSTEM; секреты не входят в дистрибутив клиента.
- `owner-access.json` в этом каталоге содержит выданный лицензионный ключ, логин и пароль админки. Не публиковать этот файл. `public-key.txt` содержит только публичный ключ.
- Клиент скомпилирован с `BOOKS_LICENSE_URL=http://127.0.0.1:8791` и этим публичным ключом. Кэш лицензии шифруется через системное хранилище Windows.

Сборка сервера: `.venv/Scripts/python.exe scripts/build_license_server.py`. Для нового локального сервера `scripts/provision_local_license.py` создаёт ключи один раз и отказывается заменять существующую конфигурацию. Перед созданием секретов ограничить права каталога текущим пользователем и SYSTEM. При обновлении сервера заменять только exe, сохраняя конфигурацию и базу. Локальный сервер не требует Docker, Python или Node при запуске.

Для второго компьютера нужен общий HTTPS-адрес. При переносе сохранять текущую пару ключей и базу; приватный ключ остаётся только на сервере. Для резервной копии остановить сервер, скопировать весь его каталог данных и затем запустить ярлык автозагрузки. Не менять ключ подписи без обновления клиентов.

Реальный VPS, домен и TLS пока не настраивались. Ниже — порядок будущего общего развёртывания.

## Подготовка

Из корня проекта:

```powershell
uv run python scripts/setup_server.py
docker compose up -d --build
```

Первый скрипт спрашивает пароль администратора (не менее 12 символов), создаёт `.env` с Argon2-хешем, ключом подписи, JWT-секретом и паролем базы, а также `server/public-key.txt`. Существующий `.env` не перезаписывается. Сохраните приватный ключ: замена ключа потребует обновить публичный ключ в клиентах.

Compose поднимает PostgreSQL 17 и API. База имеет отдельный volume и не публикует порт наружу. API доступен только через `127.0.0.1:8000`; админка находится на `/`, проверка доступности — `/health`. Для внешних клиентов нужен HTTPS reverse proxy на выбранном домене. В production запускается `server.api:from_environment`, а не тестовый сервер из `scripts/`.

Домен и публичный ключ передаются при сборке клиента через `BOOKS_LICENSE_URL` и `BOOKS_LICENSE_PUBLIC_KEY`. Приватный Ed25519-ключ не должен попадать в клиент.

## Изменение политики

`server/policy.json`: 2 устройства по умолчанию, 7 дней офлайн, проверка раз в 24 часа, месяц 30 дней, год 365 дней. Здесь же названия тарифов. После изменения файла пересоберите/перезапустите сервер. Уже выданное подписанное офлайн-разрешение действует до своего срока; отзыв без сети не может примениться за 24 часа.

Полный лицензионный ключ показывается только при выпуске и может быть выгружен в CSV в текущей сессии. В базе хранятся хеши. Обычный экспорт списка не содержит полных ключей. Пачка выпускается одной транзакцией. Чтобы снизить лимит ниже числа активных устройств, сначала отвяжите лишние устройства.

## Проверки и обслуживание

SQLite проверен автоматически и через браузер. Для PostgreSQL тесты создают уникальную временную схему и удаляют только её:

```powershell
$env:TEST_DATABASE_URL = 'postgresql+psycopg://USER:PASSWORD@HOST/TEST_DATABASE'
uv run pytest tests/test_licenses.py -q
```

Используйте тестовую базу. Без этой переменной PostgreSQL-проверки явно пропускаются. CI-конфигурация поднимает отдельный PostgreSQL service, но сам CI пока не запускался.

Проверка Compose без подключения к Docker daemon:

```powershell
$env:BOOKS_ENV_FILE = '.env.example'
docker compose --env-file .env.example config --quiet
Remove-Item Env:BOOKS_ENV_FILE
```

`.env.example` содержит нерабочие заглушки и не предназначен для запуска сервера. Конфигурационная проверка выполнена успешно. Контейнеры локально не стартовали из-за ошибки установленного Docker Desktop; reset и изменение ОС не выполнялись.

Перед эксплуатацией нужны резервные копии базы и `.env`, проверка восстановления, HTTPS и ограничение запросов на reverse proxy. Встроенный rate limit действует в рамках одного процесса; JWT админки живёт один час. Веб-панель не включает платежи или регистрацию клиентов.
