# Книжная мастерская / local-books-order

Рабочая версия подготовки EPUB, FB2 и PDF к локальной озвучке. Реальный синтез Qwen проверен на CPU и CUDA с русским текстом; добавлен ускоренный режим NVIDIA с CUDA Graphs. Узнаваемость клона, литературное качество озвучки и установщики Windows/macOS ещё не прошли приёмку.

## Открыть на этом компьютере

Десктопная Windows-версия 0.3 запускается ярлыком **Книжная мастерская** на рабочем столе или в меню «Пуск». Каталог приложения: `%LOCALAPPDATA%/Programs/LocalBooksStudio`. Интерфейс написан на Rust / egui и рисуется нативно, без React, HTML и WebView. Рядом находятся Python/CUDA runtime и FFmpeg. Модель остаётся в выбранной локальной папке; удалять её нельзя, пока она используется. Библиотека: `%APPDATA%/app.localbooks.studio`. Браузер, Node.js, Rust и виртуальное окружение для запуска не нужны. Актуальная сборка — `client/native/README.md`; прежняя сборка Tauri описана в `client/PACKAGING.md`.

На этом компьютере настроен локальный сервер лицензий `http://127.0.0.1:8791` с автозапуском при входе в Windows, годовой ключ активирован. Сохранены личный и технический голоса. Выберите книгу → голос справа → «Слушать пробу» → «Озвучить всю книгу» → «Сохранить MP3…». Запись и импорт WAV доступны на отдельном экране «Мой голос». Оформление: «Книжная полка», тёплый графит / белый, сирень, Lora + Golos Text. Тема и выбор голоса сохраняются. Администрирование лицензий описано в `server/DEPLOYMENT.md`.

### Предпросмотр для разработки

Запустите `start-preview.cmd` двойным щелчком. Он использует подготовленное окружение Python, открывает собранный интерфейс в браузере и добавляет три оригинальные тестовые книги. Токен подключения вводить не нужно. Повторный запуск открывает уже работающий экземпляр. Для остановки используйте `stop-preview.cmd` или закройте окно первоначального запуска.

Это локальный предпросмотр, не Tauri-установщик. Библиотека находится в `data/preview`. Модели не скачиваются, лицензия не обходится. Пока TTS-модуль не установлен, кнопки озвучки отключены; импорт, текст, главы, обложки и темы доступны.

Для установленного TTS-окружения есть `start-tts-preview.cmd`. Перед переключением остановите старый экземпляр через `stop-preview.cmd`: работающий предпросмотр не меняет Python-окружение при повторном открытии. Проверки лицензии действуют; для озвучки в интерфейсе нужны настроенный License API и действующий ключ. Диагностические WAV доступны отдельно в `artifacts/tts-*`.

Для ускорения откройте **Студия озвучки → Модель и оборудование**, выберите **NVIDIA (CUDA)** и **Ускоренный NVIDIA**, затем «Проверить и сохранить». «Автоматически» выбирает этот режим на CUDA при установленном пакете ускорения. Существующие задания сохраняют свой прежний движок; новое задание использует новые настройки. Перед длительной озвучкой освободите видеокарту от игр и других тяжёлых приложений.

## Ускорение NVIDIA

Используется [faster-qwen3-tts](https://github.com/andimarafioti/faster-qwen3-tts) **0.3.2**, совместимый с уже проверенными qwen-tts 0.1.1 и Transformers 4.57.3. CUDA Graphs применяются к основному декодеру и предсказателю аудиокодов. Веса модели прежние; новые модели, драйверы, CUDA Toolkit и FlashAttention не устанавливались. Фиксация зависимостей Windows включает пакет ускорения. Для существующего TTS-окружения отдельная установка:

```powershell
uv pip install --python .venv-tts/Scripts/python.exe -r requirements-tts-fast.txt -c requirements-tts-windows.lock.txt --torch-backend cu128
```

На освобождённой RTX 4070 SUPER один и тот же короткий текст дал 34,902 секунды вычислений в обычном режиме и 6,575 секунды после прогрева CUDA Graphs. Длительность аудио различается из-за сэмплирования: 19,12 и 22,48 секунды. RTF (время вычислений / длительность аудио) — 1,825 и 0,292. Это короткий контрольный запуск, не время целой книги. Измерения, длительная проверка и ограничения — в `REPORT.md`.

Модель и подготовленный голос сохраняются в памяти worker. Неиспользуемый кэш PyTorch освобождается между фрагментами; измеренный пик выделенной памяти — около 2,7 ГиБ, резервирования — 3,3 ГиБ. Нужен дополнительный запас для других приложений. Кэш аудио разделён по движкам и версии адаптера. При достижении лимита генерации/контекста неполное аудио отвергается; генерация аудиотокенов ограничена пятью минутами на фрагмент. Ошибка не запускает скрытый переход на медленный или облачный движок. Обычный режим можно выбрать явно.

Длительная проверка реальной очереди: **12 218 символов, 56 фрагментов, 14 минут 24 секунды аудио за 4 минуты 20 секунд синтеза**, RTF 0,3014. После паузы и запуска другого процесса первые три WAV сохранились, остальные 53 досинтезированы; созданы MP3/M4B. Это синтетический контрольный текст. Ориентир для 10 часов аудио при такой скорости — около 3 часов вычислений плюс запуск и экспорт. Результаты в `artifacts/fast-queue-long/report.json`, повторение — `scripts/verify_fast_queue.py start`, затем отдельным процессом `resume` в проверенном TTS-окружении. Скрипт сохраняет существующие результаты и откажется перезаписывать папку теста.

Если исходники перенесены на другой компьютер, сначала выполните `uv sync`, затем в `client/ui` — `npm ci` и `npm run build`.

## Структура
- `client/engine/`: импорт, нормализация, SQLite-библиотека, голоса, очередь, экспорт, локальный API.
- `client/native/`: действующий нативный Rust-интерфейс Windows, запись и воспроизведение звука, системные диалоги.
- `client/ui/`: прежняя React / Tauri-версия и браузерный предпросмотр; в новую программу не входят.
- `server/`: сервер лицензий и серверный конфиг тарифов.
- `shared/`: контракт подписанного разрешения Ed25519.
- `samples/`: три оригинальные искусственные тестовые книги.
- `tests/`: проверки импорта, лицензий, очереди, API и экспорта.

## Разработка
Требуются uv, Node.js; для экспорта FFmpeg в PATH. Python 3.11 устанавливается uv в пользовательское окружение, зависимости проекта изолированы в `.venv`.

```powershell
uv sync
uv run pytest -q
uv run python -m client.engine samples/night-keeper.fb2
```

Локальный обработчик (первый терминал):
```powershell
$env:BOOKS_LOCAL_TOKEN = 'задайте-случайный-токен-не-короче-32-символов'
uv run uvicorn client.engine.api:from_environment --factory --host 127.0.0.1 --port 8765
```

Интерфейс (второй терминал):
```powershell
cd client/ui
npm ci
npm run dev
```

Откройте http://127.0.0.1:5173 и введите тот же токен. В режиме разработки он хранится в sessionStorage вкладки. Исходники Tauri автоматически запускают sidecar и передают сессию через IPC; нативная оболочка ещё не скомпилирована на этом компьютере.

## Что работает

- Импорт трёх форматов, главы, разделение/объединение, локальная SQLite-библиотека и статус последней озвучки.
- Оригинал текста сохраняется; версия для озвучки допускает ручные правки, словарь, числа прописью и паузы вида `[[pause:500]]`. Сноски и колонтитулы удаляются только по выбору пользователя.
- Определение языка по главам и ручной выбор. Числа прописью поддерживают русский, английский, немецкий, французский, испанский, итальянский и португальский. Для русского добавлены даты ДД.ММ.ГГГГ, время ЧЧ:ММ, десятичные числа, дроби, проценты, суммы и распространённые единицы. Контекстные исключения требуют проверки версии для озвучки.
- WAV-профили 10–30 секунд, PCM 16-bit, ≥16 кГц; проверяются длительность, целостность и доля тишины.
- Очередь, пауза/продолжение, восстановление, проверка кэша, выбор готового фрагмента для прослушивания. Проверены техническим сигналом и настоящим ускоренным TTS на 12 218 символах с продолжением в новом процессе.
- MP3 по главам и M4B с оглавлением, автором, названием и обложкой. FFmpeg/ffprobe реально проверены.
- Удаление проекта удаляет связанные задания и неиспользуемый аудиокэш. Исходная книга, сохранённые голоса и файлы экспорта остаются.

PDF разбирается эвристически: возможны переносы строк и ошибки порядка в сложной вёрстке. OCR отсутствует. Сгенерированные тестовые книги короткие; длинная глава проверена отдельно на уровне очереди.

## Модель
XTTS-v2 не выбран для коммерческого продукта: [лицензия CPML](https://huggingface.co/coqui/XTTS-v2/blob/main/LICENSE.txt) ограничивает использование некоммерческими целями.
Кандидат — [Qwen3-TTS-12Hz-0.6B-Base](https://huggingface.co/Qwen/Qwen3-TTS-12Hz-0.6B-Base), Apache-2.0 в карточке весов; [официальный репозиторий](https://github.com/QwenLM/Qwen3-TTS) описывает русский язык и клонирование. После явного разрешения модель скачана и проверена на Windows: CPU float32 и CUDA bfloat16, SDPA. MPS пока не проверен. Старые замеры под нагрузкой и новые с ускорением на освобождённом GPU приведены отдельно в `REPORT.md`.

Каталог читает только метаданные. Проверенный размер модели вместе с токенизатором — около 2,52 ГБ. Перед скачиванием интерфейс заново показывает размер и требует подтверждение. Загрузка привязана к ревизии, проверяет размеры и SHA-256 крупных файлов; её можно остановить. Повторная попытка в ту же папку сохраняет уже полностью скачанные и проверенные файлы, а незавершённый файл скачивает заново. При синтезе используется только локальная папка, сетевое скачивание отключено.

`requirements-tts.txt` описывает базовые необязательные зависимости, `requirements-tts-fast.txt` — ускорение NVIDIA. На этом ПК они установлены в отдельное `.venv-tts`: Python 3.11.16, qwen-tts 0.1.1, PyTorch/torchaudio 2.9.1+cu128, transformers 4.57.3, faster-qwen3-tts 0.3.2. `requirements-tts-windows.lock.txt` фиксирует установленные версии всех 128 пакетов; это снимок Windows-окружения без хешей каждого пакета. `uv pip check` проходит. Установка пакетов не добавляет их в уже собранный `.exe`: нужна отдельная TTS-сборка. Драйверы и системные компоненты не менялись; SoX/FlashAttention не установлены, выбранная модель работает без них.

Воспроизведение окружения на новой Windows/NVIDIA-машине:
```powershell
uv venv .venv-tts --python 3.11
uv pip install --python .venv-tts/Scripts/python.exe -r requirements-tts-windows.lock.txt --torch-backend cu128
```

Модель находится в `models/qwen3-tts-0.6b-5d83992436ea`, ревизия `5d83992436eae1d760afd27aff78a71d676296fc`, размер 2 516 100 892 байта. Веса и токенизатор проверены по SHA-256. Для медленного соединения добавлен диагностический `scripts/resume_model_download.py`: он требует явного подтверждения ревизии и размера, продолжает сохранённый префикс файла частями и проверяет полный хеш перед принятием результата.

Повторить короткую проверку (выберите новую папку результата):
```powershell
.venv-tts/Scripts/python.exe -X utf8 scripts/benchmark_tts.py --model models/qwen3-tts-0.6b-5d83992436ea --reference data/tts-check/reference.wav --transcript data/tts-check/reference.txt --device cpu --threads 6 --output artifacts/my-tts-check --reference-label "Synthetic Windows SAPI reference"
```

На этом ПК `data/tts-check/reference.wav` — специально созданный синтетический английский образец Windows SAPI, 17,87 секунды. Это техническая проверка межъязычного синтеза, не приёмка сходства с голосом человека. Для своего образца замените WAV и точную расшифровку. Скрипт сохраняет текст, WAV и JSON с замерами; сетевые подключения во время проверки запрещены внутри процесса. Время загрузки модели и подготовки голоса отделено от времени синтеза. Параметр `--book samples/night-keeper.fb2` выбирает первую главу тестовой книги. Диагностический скрипт вызывает движок напрямую; проверки лицензии в приложении не отключаются.

## Лицензии приложения
Ключи хранятся на сервере как SHA-256, полный ключ показывается только при выпуске. Разрешение подписано Ed25519, привязано к machine ID и ограничено меньшим из срока подписки и семи дней после проверки. Отзыв требует связи; офлайн ранее выданное разрешение сохраняет силу до своего срока. Администратор освобождает активации. Политика в `server/policy.json`; месяц сейчас 30 дней, год 365 дней.

Локальное состояние шифруется ключом из Windows Credential Manager или macOS Keychain. Worker проверяет разрешение перед каждым фрагментом; проверка при запуске и обновление по истечении 24 часов подключены. Лицензия не блокирует импорт и подготовку текста. На сервер отправляются только ключ и хеш идентификатора устройства; тексты, названия книг, пути и голоса остаются локально.

При локальном выполнении кода защита от взлома — ограничение, не гарантия. Пользователь, контролирующий машину, может изменить код. PyArmor и серверный синтез не входят в v1.

## Сервер и сборки

См. `server/DEPLOYMENT.md` и `client/PACKAGING.md`. PostgreSQL поддержан в коде и CI-конфигурации, но локальные интеграционные проверки пока выполнялись на SQLite. Docker Compose прошёл проверку конфигурации; запуск контейнеров заблокирован неисправностью установленного Docker Desktop.

В `build/sidecar/books-engine.exe` находится проверяемая Windows-сборка обработчика. Это служебный процесс, а не окно приложения; двойной щелчок по нему не заменяет установщик.

## Достоверность проверок
Искусственные книги не заменяют тесты на реальных издательских файлах. Автотесты очереди используют технический сигнал; отдельно выполнены реальные TTS-запуски с аудио и замерами. Узнаваемость клона и естественность русской речи требуют слуховой приёмки. Смотрите `REPORT.md` для фактически выполненных проверок и оставшихся ограничений.
## Запись своего голоса

В установленной программе откройте «Голос и озвучка» → «Записать мой голос с микрофона». Прочитайте предложенный текст целиком за 15–25 секунд, остановите запись, прослушайте и нажмите «Сохранить мой голос». При первом запросе разрешение на микрофон даёт пользователь. Голос автоматически выбирается для текущей озвучки; позже его можно выбрать в списке «Голос».

Запись сохраняется локально как PCM WAV, моно, 24 кГц, 16 бит, вместе с точной расшифровкой контрольного текста. Минимум 10 секунд, автоматическая остановка через 30 секунд. При закрытии панели, уходе из студии или скрытии окна микрофон останавливается. Готовый WAV по-прежнему можно добавить через «Добавить голос».

Проверка `scripts/recorder-smoke.cjs` использует искусственный микрофон Chromium с синтетическим WAV, проверяет отказ в доступе, короткую запись, преобразование и сохранение, отключение дорожек при отмене, предел 30 секунд и узкий экран. Физический микрофон и сходство с личным голосом требуют записи пользователя.


## Очистка шума и чтение чисел

В студии включена «Убирать фоновый шум»: мягкий фильтр применяется к копии образца перед клонированием и к готовой речи. Исходный `reference.wav` не меняется, очищенный образец кешируется отдельно. Можно отключить очистку для сравнения. Разные режимы и версии обработки не используют один аудиокеш; старые задания и MP3 сохраняются.

Очистка основана на локальном [FFmpeg afftdn](https://www.ffmpeg.org/ffmpeg-filters.html#afftdn) и высокочастотном пропускном фильтре 65 Гц. Она рассчитана на постоянный фон и низкочастотный гул, не является универсальным удалением музыки, чужой речи или эха. Учтена задержка FFT, чтобы сохранить конец фразы и длительность. Новых моделей и облачных сервисов нет.

«Числа, даты и время прописью» включены для новых книг и в API по умолчанию. Ранее сохранённый выбор пользователя сохраняется. Подготовленный текст доступен в редакторе до запуска. Для русского используются [num2words и его правила падежей](https://github.com/savoirfairelinux/num2words/blob/master/tests/test_ru.py), дополненные контекстными правилами приложения. Примеры: `09:05` → «девять часов пять минут», `21%` → «двадцать один процент», `1 250,50 ₽` → «одна тысяча двести пятьдесят рублей, пятьдесят копеек», `Глава 1` → «Глава первая».

Ограничения: это набор правил, а не полный морфологический разбор русского. Сложные падежи, телефонные номера, римские числа, названия вроде «1984», неоднозначные диапазоны и специальные обозначения требуют ручной правки версии для озвучки. Некорректные даты, URL, буквенно-цифровые идентификаторы и команды пауз сохраняются. На других языках остаётся прежнее преобразование простых целых чисел.

Проверки: `tests/test_speech_processing.py` проверяет форматы чисел, неизменность источника, паузы, разделение кеша и шумоподавление на сигнале с известным шумом. `scripts/verify_speech_quality.py` выполняет реальную локальную озвучку с существующей лицензией; он привязан к этому рабочему месту и личному сохранённому голосу, не предназначен для CI.
